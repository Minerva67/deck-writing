# deck-writing：写 PPT 之前先把结论和结构定下来

让 Claude 做 PPT，常见的结果是：页面看着整齐，但读的人抓不到重点。标题是「关于用户留存」这样的话题，一页讲两件事，同一个东西前后三个叫法，并列的几项被画成了流程。

这个 skill 是一套写 deck 的规范。它要求 Claude 先想清楚读者和结论，再动手画页面；写完按清单自查，再交给你。

适用于给别人自己翻看的 deck：业务介绍、合作方案、服务说明、融资 deck、诊断和汇报。

## 流程

| 步骤 | 做什么 |
|---|---|
| 1 写三行 | 读者是谁、看完做什么、读者关心的结果。写不出第三行不动手 |
| 2 出分镜 | 每页一行：结论句标题、用什么图、证据从哪来。确认后再画 |
| 3 组织每页信息 | 一页一个结论；用读者自己的流程做骨架；证据挂在它要证明的那句话下面 |
| 4 写标题 | 标题是能被判断对错的完整句子，30 字以内 |
| 5 过语言 | 平实、清晰、客观、书面四条，附四问自检 |
| 6 核数字 | 每个数字有来源、年份、定义；全 deck 口径和名称一致 |
| 7 定视觉 | 只有几条通用规则，不绑定某一种风格 |
| 8 制作和自查 | 渲染后检查断行、溢出和空白；发布前保留对方的手改 |
| 9 回复 | 说明哪些是照搬、哪些是新写的、哪些待核对 |

## 文件

| 文件 | 内容 |

## 安装

把整个目录复制到 `~/.claude/skills/deck-writing/`。之后对 Claude 说「做个 PPT」「这页太乱」「加一页」，它会先按这套规范走。

导出脚本需要本机装有 Google Chrome；生成总览图需要 PyMuPDF（`pip install pymupdf`）。脚本里的 Chrome 路径是 macOS 的默认位置，其他系统需要自己改。

## 说明

这套规范是从多次返工里整理出来的，偏向中文、给人自己读的 deck。现场演讲用的大字少字型 slides 不完全适用。
