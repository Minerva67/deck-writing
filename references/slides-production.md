# 制作要点（Claude Slides 类型的 deck）

用 Artifact 的 Slides 类型时，以它返回的官方说明为准。下面是实测过、容易踩的地方。

## 文件结构

- `project/deck.json`：标题、`order`（页的顺序）、`sections`、`faces`（字体，最多 4 个家族）。
- `project/deck.css`：全 deck 共用的样式。新建的 deck 用带 `format` 的写法（class 样式）；已有页面但没有 `format` 的旧 deck 只能写内联样式，不要给它加 `format`。
- `project/slides/<id>.html`：一页一个 `<section id="<id>">`，画布 1920×1080，四周留白 128px，可用区域 1664×824。备注放在最后一个 `<aside>` 里。

## 写页面时

- 字号不小于 24px。
- 一行里的一小段文字只能改颜色、加粗、斜体、下划线。要做胶囊标签，单独用一个 `<p>` 加底色、内边距和圆角。
- 文字只在空格处换行。中文标题按「字号 × 字数」估宽度：46px 的标题一行约放 36 个汉字，西文字符按半个算。放不下就改短，不缩字号。
- 卡片不要写死高度。同排卡片要等高时，用网格加 `flex: 1` 的占位块把内容顶到底部。
- 背景装饰（光晕、色块）用绝对定位，并且写在该页的最前面。它在 Slides 里会垫在正文下面。
- 渐变只用一层普通渐变；不用 `z-index`、`clip-path`、背景图。
- 图片和 logo 先上传成素材，页面里用返回的 `/_blob/<id>` 地址，不用 data URI 和外链。
- 页码用绝对定位的一个 `<p>`，每页位置相同。

## 改已有的 deck

1. 先读线上版。读 `project/deck.json` 拿到顺序，再读要改的那几页。
2. 在读到的版本上改。用户在页面上保存过的页，编辑器会改写字体栈和颜色写法，照它现在的样子改，不要整页覆盖回自己的旧稿。
3. 只发改过的文件。增删页时同时发 `deck.json`。
4. 发布被拒绝，说明用户刚保存过：按提示重读，在用户的版本上重做这次改动，再发。
5. 用户删掉的页和句子不加回来。

## 本地渲染和导出 PDF

Slides 页面没法在本地直接打开，用脚本把所有页拼成一个 HTML，再用无头 Chrome 打印：

```bash
python3 ~/.claude/skills/deck-writing/scripts/export_pdf.py <deck 根目录> <输出.pdf> [素材对照.json]
```

- `<deck 根目录>` 是放着 `project/` 的那个文件夹。
- 素材对照是一个 JSON：`{"<blob id>": "/本地/文件/路径"}`。不给的话，`/_blob/` 的图片在本地显示不出来。
- 脚本会同时生成一张缩略总览图（同名 `_sheet.png`），用它检查所有页。
- 只支持带 `deck.css` 的 deck 和内联样式的 deck；字体从 `faces` 里的 Google Fonts 链接加载，需要联网。

本地渲染和线上有一处已知差别：绝对定位的背景装饰在本地会盖在正文上面。脚本已经把 `.glow` 和带 `data-backdrop` 的元素压到底层；用了别的类名做背景时，给它加上 `data-backdrop` 属性。

导出的 PDF 是本地渲染的结果。交付前说明这一点；重要的版本请用户在页面上用 Share › Export 再导一次。
